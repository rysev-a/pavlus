## События — это данные

Страница, которая только показывает значения, — это документ. Чтобы сделать её интерактивной, шаблон должен сказать: «когда пользователь делает это, сообщи приложению». В pavlus это делается с помощью **привязки события**, и отправляется не функция. Отправляется *message*: небольшой кусок обычных данных с id и необязательным payload.

Привязка события — это атрибут, имя которого начинается с `@`. Часть после `@` — это событие DOM (`click`, `input`, `submit`, `keydown`, ...). Значение — id message, который нужно отправить.

::demo click open=vnodes

Посмотрите на vnodes: элемент кнопки в результате `render` содержит `events: { click: { id: "save" } }`. Функции в нём нет. Шаблон не знает, что делает `save`. Он лишь говорит, какой message означает клик. В вашем приложении есть handler для `save`, и он решает, что менять в state.

У такого дизайна есть причина. Виртуальный узел, который состоит только из данных, можно сравнивать, записывать в лог, фиксировать и воспроизводить. Шаблон остаётся чистой функцией от state, а вся логика остаётся в одном месте, в компонентах, где её легко тестировать.

## Отправка значения вместе с message

Большинству событий нужно сказать, *какая* вещь была нажата. Привязка может выглядеть как вызов с **аргументами**. Аргументы — обычные [выражения](page:syntax-expressions), вычисляемые на state при рендеринге шаблона. Результат едет вместе с message как его **payload**.

::demo payload open=vnodes

Кнопка Remove несёт `{ id: "remove", payload: 1 }`: значение `item.id` в момент рендеринга. Когда пользователь кликает, handler для `remove` получает этот payload и знает, какой элемент удалить.

Посмотрите на первый шаг. Когда `item.id` меняется с 1 на 2, `diff` возвращает patch с операцией `handler`:

```text
{"op":"handler","id":"3","event":"click","msg":{"id":"remove","payload":2}}
```

Listener уже висит на настоящем элементе DOM. Patch лишь заменяет message, который listener будет отправлять. Во втором шаге меняется заголовок, а payload — нет, и единственный patch — текстовый.

### Несколько аргументов

С одним аргументом payload — это это значение. С двумя и более payload — **массив** из них, по порядку.

::demo several-args

Payload здесь — `[5, "up", 1]`. Без аргументов или с пустыми скобками payload нет вообще, поэтому `@click=save` и `@click=save()` одно и то же.

::demo empty-parens

> [!NOTE] Одно значение или массив
> Форма payload зависит от того, сколько аргументов вы написали: один аргумент даёт это значение, два и более дают массив. Если вы планируете позже добавить второй аргумент, помните, что handler придётся изменить с `msg.payload` на `msg.payload[0]`. Поэтому многие авторы отправляют одно значение или один объект, собранный в state.

## Что можно писать в качестве handler

Часть перед скобками — это **id message**. Это имя или имена, соединённые точками:

::demo dotted

Здесь id — `users.open`. Id с точкой удобен для группировки messages, и именно он заставляет работать префикс компонентов (см. ниже).

Компилятор принимает только имя или цепочку имён, за которыми необязательно идёт вызов. Всё остальное — ошибка:

```pavlus-invalid
button(@click=ready ? start : stop) Go
```

Здесь ошибка возникает в парсере атрибутов: `Unexpected "?" in attributes (line 1, col 21)`, потому что голое значение заканчивается на первом пробеле. В фигурных скобках оно доходит до следующей проверки с таким сообщением:

```pavlus-invalid
button(@click={ready ? start : stop}) Go
```

```text
Event handler must be a message id like `save` or `remove(item)` (line 1, col 8)
```

То же сообщение выводится для `@click=items[0]` и для вызова вызова, `a.b(1)(2)`. Привязка совсем без значения, `button(@click)`, выдаёт `"@click" needs an expression value`.

## Модификаторы: prevent и stop

Браузер делает кое-что сам. Клик по ссылке переходит по ссылке. Отправка формы перезагружает страницу. Клик также всплывает к родителям элемента, и их обработчики тоже выполняются. Часто это хочется отключить.

Это можно сделать с помощью **модификаторов**, которые пишутся после имени события и разделяются точками:

| Модификатор | Что делает |
| --- | --- |
| `.prevent` | вызывает `preventDefault()` у события DOM: ссылка не открывается, форма не отправляется |
| `.stop` | вызывает `stopPropagation()`: listeners родителей не видят событие |

Их можно сочетать в любом порядке: `@click.prevent.stop=openHelp`.

::demo modifiers open=vnodes

Посмотрите на vnodes. Модификаторы не входят в имя события. Это два флага на message, `prevent: true` и `stop: true`. DOM plugin читает их, когда происходит событие, вызывает метод DOM и только потом отправляет message. Так и здесь страница остаётся чистыми данными.

Неизвестный компилятору модификатор молча игнорируется: `@click.foo=save` — то же самое, что `@click=save`. Проверьте написание `.prevent`, если форма всё ещё перезагружает страницу.

> [!WARNING] Несколько привязок для одного события
> У одного элемента может быть много разных событий (`@input`, `@keydown`, `@focus`), но только одна привязка на имя события. Если вы напишете `@click` дважды на одном элементе, победит последняя, а первая будет отброшена без ошибки.

::demo many-events

## Что получает handler

Когда пользователь кликает, DOM plugin отправляет вашему приложению объект message с тремя полями:

| Поле | Значение |
| --- | --- |
| `id` | id message, перед которым стоит префикс встроенных компонентов |
| `payload` | payload из шаблона или `undefined` |
| `event` | небольшой снимок события DOM |

Снимок, `msg.event`, — единственное место, где браузер просачивается в вашу логику, и он намеренно мал: `type` (имя события), `value` (значение `value` элемента, когда это строка), `checked` (для чекбоксов) и `key` (для событий клавиатуры). Для форм этого достаточно.

Компонент — это класс. **Каждый метод — handler для message с тем же именем.** Handler чистый: он получает message и текущий state и возвращает список effects, например «запиши этот путь в store».

```ts todo.ts
import {
  Component,
  type Message,
} from "@service-laboratory/pavlus";
import { storeEffector as store } from "@service-laboratory/pavlus/plugins";
import view from "./todo.pavlus";

interface State {
  text: string;
  tasks: { id: number; title: string }[];
}

class Todo extends Component<State> {
  view = view;

  setText(msg: Message) {
    return [store.set("text", msg.event?.value ?? "")];
  }

  remove(msg: Message, state: State) {
    return [
      store.set(
        "tasks",
        state.tasks.filter((t) => t.id !== msg.payload),
      ),
    ];
  }
}
```

В шаблоне этого компонента есть `input(value=text @input=setText)` и `button(@click=remove(task.id))`. Имена совпадают с именами методов. Message без метода — не ошибка: ничего не происходит, effects не возвращаются. Из-за этого опечатка в id message остаётся тихой, поэтому проверяйте страницу кликами.

State, показанный в поле ввода, — лишь начальное значение. То, что набрал пользователь, хранит браузер. Handler `@input` копирует это в state, а state поддерживает остальную часть приложения актуальной.

## События в циклах

События внутри цикла `for` — самый частый случай. Payload — это то, что говорит handler, по какому элементу кликнули.

::demo in-loop open=vnodes

У каждой задачи своя пара кнопок, и payload каждой — `id` своей задачи: 10 у первой и 20 у второй. Есть один handler для `toggle`, а не по функции на строку, и он работает для любого числа строк. `.stop` на второй кнопке не даёт клику дойти до элемента списка, если бы у элемента был собственный handler.

Почему `task.id`, а не позиция задачи в списке? Когда список меняется, позиции меняются, а id — нет. Message, который несёт id, всегда означает одну и ту же задачу. Смотрите также [следующую страницу](page:syntax-control-flow) о `key`.

## Откуда у id message берётся префикс

Когда шаблон встраивается в другой через `+Name#instance`, встроенный шаблон — это отдельный файл со своими messages: он говорит `@click=pick(id)` и не знает, кто его будет использовать. Родитель даёт каждому встроенному экземпляру **имя**, и компилятор ставит это имя и точку перед каждым id message, который из него выходит.

::demo with-component open=vnodes

Шаблон `Row` отправляет `pick`. Два экземпляра названы `first` и `second`, поэтому messages — `first.pick` и `second.pick`. Кнопка `Reset` принадлежит родителю и не имеет префикса. Сгенерированный модуль показывает, как это работает:

```ts
ulChildren.push(...Row.render(
  { "id": 1, "label": "One" },
  idSuffix + "/1",
  messagePrefix + "first.",
  childEnv(env, "first", state),
));
```

У каждого скомпилированного view есть параметр `messagePrefix`. Корневой view получает пустой. Embed передаёт `messagePrefix + "first."`, а каждое событие записывается как `id: messagePrefix + "pick"`. Если бы `Row` сам что-то встраивал, префикс вырос бы ещё на одно имя: `first.cell.pick`. Дочернему шаблону не нужно знать о своих родителях, поэтому один и тот же шаблон можно поместить куда угодно.

Если вы не пишете `#name`, именем становится импортированное имя с первой буквой в нижнем регистре:

::demo default-name

Первый embed отправляет `userCard.open`, второй, с `#admin`, отправляет `admin.open`. Используйте явное имя для любого шаблона, который вы встраиваете больше одного раза, чтобы messages экземпляров можно было различить.

На стороне приложения префикс используется, чтобы отправлять messages вниз нужному дочернему компоненту и чтобы дать родителю способ следить за messages своих дочерних компонентов через handler с именем в кавычках, например `"first.pick"(msg) { ... }`. Это описано в [компонентах](page:concepts-components) и [сообщениях](page:concepts-messages).

## Что остаётся прежним, а что меняется

Сравните две вещи, которые вы видели на этой странице. У привязки без аргументов (`@click=save`) нет `id` на её элементе в vnode, потому что в ней ничего не может измениться, поэтому `diff` никогда не нужно её искать.

::demo static-event

Когда `busy` меняется, создаётся только patch класса. На привязку события даже не смотрят. Привязка с аргументами — другое дело: компилятор запоминает id элемента и, когда `diff` находит другой payload, выдаёт один patch `handler`. Узел, привязки, атрибуты и текст которого не могут измениться, ничего не стоит при обновлении.

## Собираем вместе

Небольшой список с полем ввода, использующий то, что вы увидели. Шаблон такой, и такую же форму можно попробовать в [песочнице](page:compiler-playground):

```pavlus
section.todo
  form(@submit.prevent=add)
    input(type="text" placeholder="New task" value=text @input=setText)
    button(type="submit") Add
  ul
    for task in tasks key task.id
      li(class:done=task.done)
        input(type="checkbox" checked={task.done} @change=toggle(task.id))
        span {task.title}
        button(type="button" @click.stop=remove(task.id)) x
```

Прочитайте события сверху:

- `@submit.prevent=add` не даёт браузеру перезагрузить страницу, затем отправляет `add`. Handler читает текст из state, потому что `@input=setText` копирует его туда при каждой клавише.
- `@input=setText` отправляет `setText` с `msg.event.value`.
- `@change=toggle(task.id)` отправляет `toggle` с id задачи. Handler может также прочитать `msg.event.checked`.
- `@click.stop=remove(task.id)` отправляет `remove` с id и не даёт клику всплыть.

Здесь четыре id message и три payload, и ни одной функции в шаблоне.

## Что вы узнали

- `@event=name(args)` отправляет message, а не функцию. Один аргумент — это payload, несколько аргументов образуют массив, без аргументов payload нет.
- `.prevent` и `.stop` — это флаги на message; DOM plugin применяет их, а затем отправляет message.
- Handler — это метод компонента, названный по id message; он получает `msg.id`, `msg.payload` и небольшой `msg.event` (`type`, `value`, `checked`, `key`).
- Встроенный шаблон отправляет свои messages с именем экземпляра в качестве префикса: `first.pick`.
- Когда payload меняется, `diff` возвращает patch `handler`; привязка без аргументов никогда не получает patch.
