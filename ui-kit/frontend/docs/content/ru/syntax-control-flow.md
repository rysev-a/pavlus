## Выбор того, что есть на странице

До сих пор каждая строка шаблона присутствовала всегда. Реальным страницам нужны ещё две возможности: показывать блок *только когда* что-то истинно и показывать блок *по разу для каждого элемента* списка. В pavlus для каждой есть своё ключевое слово: `if` и `for`. Это не элементы. Они не создают собственного тега. Они только решают, какие из их дочерних строк существуют.

Оба берут строки с отступом под собой в качестве тела, так же как это делает элемент.

## if

Простейшее условие — `if`, за которым идёт [выражение](page:syntax-expressions). Когда значение истинно, тело рендерится; когда нет, тела на странице нет вообще.

::demo if-simple

Посмотрите на два шага. Когда `loggedIn` меняется с `true` на `false`, `diff` возвращает один patch, `clear`, который удаляет всё между двумя маркерами с именами `0s` и `0e`. Когда оно возвращается к `true`, `diff` возвращает patch `insert` со свежеотрендеренным `p`.

Маркеры — это невидимые узлы-комментарии, которые компилятор добавляет вокруг каждого `if` и каждого `for`. Они позволяют patch сказать «замени то, что между этими двумя точками», не зная, что там находится. В HTML демо они не видны, но есть в vnodes, и вы увидите их в patches на этой странице.

Завершающее двоеточие допускается и ничего не значит: `if loggedIn:` — то же самое, что `if loggedIn`.

> [!NOTE] Истинность
> Условие следует правилам JavaScript: `0`, `""`, `null`, `undefined`, `false` и `NaN` ложны. Пустой массив истинен, поэтому для проверки «есть элементы» пишите `if items.length`.

## else и else if

Строка `else if` или `else` продолжает `if` выше неё. Они должны стоять с тем же отступом, что и `if`, сразу после его тела.

::demo if-else

Первый шаг заменяет всё приветствие сообщением о входе: ветка изменилась, поэтому содержимое между маркерами заменяется. Второй шаг сохраняет ту же ветку, и обновляется только текст внутри неё. Компилятор различает эти две ситуации и никогда не рендерит заново ветку, которая осталась прежней.

Ветки пробуются по порядку, и побеждает первое истинное условие. У ветки `else` нет условия, и она должна быть последней.

::demo else-if open=module

Откройте модуль и найдите `prevBranch` и `nextBranch`. Для каждого из двух state сгенерированный код вычисляет *номер ветки*, которая показывается (здесь от 0 до 3, или -1, если `else` нет и ничего не подошло):

```ts
const prevBranch = (prev.status === "loading") ? 0 : (prev.status === "error") ? 1 : ((prev.items)?.length === 0) ? 2 : 3;
const nextBranch = (next.status === "loading") ? 0 : (next.status === "error") ? 1 : ((next.items)?.length === 0) ? 2 : 3;
```

Если два числа различаются, ветка заменяется: `clear` между маркерами, затем `insert` новой ветки, отрендеренной с нуля. Если они одинаковы, патчатся только изменения внутри этой ветки. Шаг «items 2 → 5» делает именно это: один patch `text`, больше ничего.

Ошибка, о которой парсер сообщает сам, — это `else`, которому нечего продолжать:

```pavlus-invalid
p First
else
  p Second
```

```text
`else` without matching `if` (line 2, col 1)
```

Та же ошибка появляется, когда за `else` следует второй `else` или когда за `else` следует `else if`. Строка между `if` и его `else` тоже разрывает цепочку.

`if` внутри элемента — просто его дочерний узел, а остальные дочерние узлы элемента остаются на месте:

::demo if-inside

Когда `subtitle` становится непустой строкой, происходит единственный patch `insert` на месте `if`, между заголовком и футером. Маркеры — причина, по которой он оказывается на правильной позиции.

## for

`for` повторяет своё тело для каждого элемента списка. Заголовок имеет вид `for item in list`: имя для текущего элемента, слово `in` и выражение, дающее список.

::demo for-simple

Внутри тела `name` — текущий элемент. Это *переменная цикла*: она существует только внутри цикла и скрывает поле state с тем же именем, если оно есть. В теле может быть любое количество строк и любая структура.

Если вам нужна ещё и позиция, назовите её после запятой:

::demo for-index

`i` считает с 0. Здесь `{i + 1}` делает номер для человека. Индекс — обычное значение выражения, как любое другое.

### Пустые и отсутствующие списки

Пустой список ничего не рендерит. Список, равный `null` или `undefined`, то же самое, что пустой, поэтому state, который ещё загружается, не ломает страницу.

::demo for-missing

Первый шаг следующего демо добавляет имя в пустой список. `ul` остаётся, а новый `li` вставляется между маркерами цикла:

::demo for-empty

Если вы хотите показать сообщение вместо пустого списка, поместите цикл в одну из веток `if`:

::demo for-if-else

Когда список не является массивом, результат зависит от его формы: строка читается по буквам, а объект без `length` ничего не рендерит. Храните настоящие списки в state.

> [!WARNING] Слова, похожие на ключевые
> Циклом является только `for x in list`. Строка вроде `for x of list` не подходит, и парсер читает `for` как имя тега элемента: на странице появляется `<for>` и нет никакой ошибки. То же верно для одинокого `if`, после которого ничего нет. Если цикл не появляется, проверьте слово `in`.

## Почему важны key

Список меняется со временем: элементы добавляются, удаляются и переставляются. Когда `diff` сравнивает старый и новый списки, он должен решить, какой старый элемент соответствует какому новому. Это решение принимается с помощью **key**.

Key добавляется в заголовок после списка: `for task in tasks key task.id`. Это выражение, вычисляемое для каждого элемента, и оно должно быть уникальным в списке и оставаться тем же для той же вещи. Идеально подходит id из ваших данных.

::demo keyed-reorder

Прочитайте каждый шаг.

1. Последний элемент перемещается в начало. `diff` возвращает два patches `move`: он перемещает существующие узлы DOM. Он ничего не создаёт, не удаляет и не переписывает текст, поэтому всё, что живёт на этих узлах (поле ввода в фокусе, выделение текста, идущая анимация), сохраняется. Алгоритм простой, а не минимальный: чтобы вывести последний элемент вперёд, он перемещает два других после него, и порядок получается тот же.
2. Первый элемент удаляется: один patch `remove` только для этого элемента.
3. Новый элемент в конце: один patch `insert`.
4. Заголовок элемента 2 меняется: один patch `text`. Id текстового узла — `3#2`: id шаблона, `#` и key.

Теперь тот же список **без** key:

::demo unkeyed-reorder

Без `key` key каждого элемента — его **позиция**. Элемент 0 остаётся элементом 0, что бы он ни содержал. Поэтому когда последний элемент перемещается в начало, `diff` видит три элемента с изменившимся текстом и переписывает три текста (`3#0`, `3#1`, `3#2`). Когда удаляется первый элемент, он удаляет *последний* элемент и переписывает остальные, потому что элементы были опознаны по позиции.

Для списка из простого текста это даёт верный результат, только с большим объёмом работы. Для списка с состоянием в DOM, например с полями ввода или проигрываемым видео, результат неверный: набранный текст остаётся в первом поле, но данные первого элемента теперь принадлежат второму.

> [!TIP] Практическое правило
> Если элементы можно добавлять, удалять или переставлять или если они хранят какое-либо состояние, дайте циклу key из ваших данных. Используйте индекс только для списка, который никогда не меняется.

Key сравниваются как текст (`String(key)`), поэтому `1` и `"1"` — один и тот же key. Они должны быть уникальными: если два элемента дают один key, `diff` выбрасывает `pavlus: duplicate key 1`. Первый `render` такого списка не проверяет, а первый `diff` проверяет, поэтому ошибка проявляется, когда список меняется.

Key может быть любым выражением, например склейкой двух полей:

## Циклы внутри циклов

Циклы вкладываются. У каждого своя переменная, а внутреннее тело видит переменные обоих.

::demo nested

Внешний цикл использует в качестве key имя группы, внутренний — сам элемент. `group.name` используется внутри внутреннего тела. В этом шаге в одной группе появляется новый элемент, и `diff` создаёт для него один patch `insert`. Id маркеров, такие как `4e#Veg`, несут key внешнего элемента, поэтому две группы никогда не смешиваются.

## Переключение классов внутри цикла

Атрибут `class:name=condition` из страницы об [элементах](page:syntax-elements) работает так же внутри цикла, с переменной цикла.

::demo class-toggle

Значение атрибута без кавычек заканчивается на первом пробеле. В `task.id === currentId` есть пробелы, поэтому его нужно обернуть в фигурные скобки: `class:current={task.id === currentId}`. Без них парсер останавливается на первом пробеле и сообщает `Unexpected "=" in attributes`.

Посмотрите на два шага. Когда `currentId` переходит с 2 на 3, у одного элемента класс убирается, а другому добавляется. Во втором шаге значение `class` элемента 2 становится `done current`: все переключатели элемента собираются в один атрибут `class`, и один patch записывает значение целиком.

## Фильтрация с if внутри for

В языке шаблонов нет `filter` (для него понадобилась бы стрелочная функция). Но `if` может быть единственным дочерним узлом `for`: тогда каждый элемент показывается, только когда выполняется его условие. Это хороший способ фильтровать короткий список.

::demo filtered open=ast

Прочитайте шаблон сверху. Поле поиска отправляет `setQuery` при каждой клавише. `for` использует `task.id` в качестве key. Внутри него `if` скрывает задачи, не подходящие под запрос (`!query` заставляет пустой запрос подходить всему). После списка второй `if` показывает счётчик или сообщение, когда ничего не подошло.

В первом шаге пользователь вводит `es`. `diff` возвращает:

- patch `attr` для значения поля ввода;
- два patches `clear`, которые опустошают `if` элементов 1 и 3, больше не подходящих: элементы остаются в списке, но их содержимого нет;
- один patch `text` для счётчика.

Во втором шаге ничего не подходит. Последний оставшийся элемент очищается, а ветка счётчика меняется с `else` на сообщение «No task matches».

Счётчик, `shown`, — обычное поле state, вычисляемое handler `setQuery` в вашем компоненте. Шаблон не может посчитать подходящие элементы, потому что он может только вычислять выражения, а циклов, возвращающих значения, у него нет. Таково обычное разделение: handler вычисляет, шаблон показывает.

Когда список длинный, фильтруйте в handler и передавайте шаблону только то, что видно. Тогда в цикле только показываемые элементы, а изменение фильтра — это набор patches `insert` и `remove`:

::demo filtered-visible

Оба подхода дают корректные страницы. Первый оставляет всю работу в шаблоне, второй сохраняет DOM небольшим.

## Собираем вместе

В этом inbox есть состояние загрузки, состояние ошибки, список, условие для каждого элемента и сообщение о пустоте. Он использует всё, что есть на этой странице.

::demo inbox

Пройдите по шагам:

1. **Загрузка → готово.** Ветка меняется с первой на третью, поэтому `p` очищается и вставляется `ul`. Он рендерится один раз, с обоими письмами.
2. **Письмо 2 прочитано.** Только два patches: класс `unread` убирается с элемента (`rmAttr`), а кнопка `Mark as read`, которая находится в `if`, очищается. Ничего больше не затрагивается.
3. **Новое письмо приходит сверху.** Один patch `insert`, помещённый перед элементом с key 1.
4. **Все письма удалены.** Два patches `remove` и вставляется сообщение «Nothing here».
5. **Ошибка.** Третья ветка заменяется второй: список очищается и вставляется сообщение с кнопкой повтора.

Шаблон говорит, как выглядит страница для каждого state. Компилятор вычисляет наименьший набор изменений между любыми двумя состояниями, и это те patches, которые вы видели.

## Что вы узнали

- `if`, `else if` и `else` показывают одну ветку. Другая ветка — это `clear` и `insert`; та же ветка — это только изменения внутри неё.
- `for item, i in list key expr` повторяет тело. Пустой или отсутствующий список ничего не рендерит.
- Key идентифицирует элемент между двумя состояниями. С key `diff` перемещает, вставляет и удаляет элементы целиком; без него key — это позиция, а содержимое переписывается.
- `if` внутри `for` фильтрует, счётчик или производный список принадлежат state, а значению с пробелами в атрибуте нужны фигурные скобки.
