## Дырка в тексте

Шаблон, который всегда говорит одно и то же, не слишком полезен. Чтобы показать значение из state, поместите **выражение** в фигурные скобки. Скобки и то, что внутри них, называются *интерполяцией*, или дыркой: компилятор оставляет в тексте дырку и заполняет её значением при каждом рендеринге шаблона.

Простейший случай — одно имя. `name` — это не текст, а поле `name` из state.

::demo hello

Посмотрите на два шага. Когда `name` меняется с Ann на Bob, `diff` возвращает один patch, который заменяет текст. Когда `name` «меняется» на то же значение, `diff` не возвращает ничего: компилятор сгенерировал проверку, которая сравнивает старый и новый текст и выдаёт patch только когда они различаются.

Всё между `{` и `}` разбирает сам pavlus. Это **не** JavaScript, выполняемый через `eval`: это маленький чистый язык со своим парсером, а компилятор переводит его в обычный JavaScript. Остальная часть страницы описывает этот язык.

## Где разрешены дырки

Дырка может быть в трёх местах:

- в тексте: после тега (`p Hello, {name}`) и в строках текста с `|`;
- в значении атрибута в кавычках: `title="Open {user.name}"`;
- как целое значение атрибута: `alt={user.name}` или `src=user.avatar`.

Переключатели классов (`class:late=order.late`), аргументы `@event`, условия `if`, списки `for` и props компонентов тоже принимают выражение. Они описаны на своих страницах.

::demo in-attributes

Во второй строке у `src=user.avatar` нет ни скобок, ни кавычек. Голое значение — это выражение, и оно заканчивается на первом пробеле, поэтому должно быть одним «словом» (без пробелов). Когда внутри выражения нужны пробелы, оберните его в скобки: `alt={user.name}`. Обе формы означают одно и то же.

> [!NOTE] Кавычки определяют, чем является значение
> `alt="user.name"` — это буквальный текст `user.name`. `alt=user.name` и `alt={user.name}` читают state. `alt="{user.name}"` тоже читает state, и есть небольшое отличие, описанное ниже в разделе о значениях атрибутов.

## Имена и доступ к членам

Голое слово в выражении — это **имя**. Оно ищется в state, который вы передаёте в `render`, а внутри цикла `for` может быть также переменной цикла (см. [условия и циклы](page:syntax-control-flow)). Точка читает свойство значения.

::demo members

Phone и zip вообще отсутствуют в state, и ничего не сломалось. Каждая точка в pavlus **null-safe**: `user.phone.number` компилируется в `((state.user)?.phone)?.number`, поэтому если любой шаг по пути равен `null` или `undefined`, всё выражение равно `undefined`, а `undefined` рендерится как ничто. Вам никогда не нужно писать защиту вроде `user && user.phone && user.phone.number`.

Выражение `?.` тоже принимается и означает то же, что и `.`:

```pavlus
p {user?.name} is the same as {user.name}
```

Благодаря этому шаблон никогда не падает из-за неполного state. Это удобно, пока данные ещё загружаются. Но это также значит, что опечатка в имени поля не приводит к громкой ошибке: она рендерится как пустой текст. Если значение не появляется, сначала проверьте написание.

> [!TIP] Чтения отслеживаются по корневому имени
> Компилятор записывает, какие имена читает выражение. `user.address.city` читает `user`. Когда `diff` сравнивает два state, он сначала спрашивает: «`prev.user` — тот же объект, что и `next.user`?» Если да, узел пропускается целиком. Если это новый объект, текст пересчитывается и сравнивается, и patch создаётся, только если результат отличается. Поэтому в state нужно заменять объекты, а не менять их на месте.

## Литералы

Выражение может содержать литеральные значения.

| Вид | Примеры | Примечания |
| --- | --- | --- |
| число | `0`, `42`, `3.14`, `.5`, `1e3` | всегда число JavaScript |
| строка | `"text"`, `'text'` | оба вида кавычек; `\n`, `\t` и `\r` — escape-последовательности, `\x` для любого другого `x` — это просто `x` |
| булево | `true`, `false` | |
| пустое | `null`, `undefined` | слова, как в JavaScript |
| массив | `[1, 2, 3]`, `[a, b]` | элементы — выражения |

Нет литералов объектов (`{ a: 1 }`), нет регулярных выражений и нет шаблонных строк с обратными кавычками.

Строки полезны для запасного значения оператора или для текста ветки тернарного оператора, как вы увидите ниже. Фигурные скобки внутри строки не завершают дырку: `{"}"}` — это дырка, которая печатает закрывающую скобку.

## Доступ по индексу и вызовы

Квадратные скобки читают элемент по позиции или по ключу. Индекс — это выражение, поэтому он может приходить из state. Как и точка, индекс null-safe.

::demo indexing

Вызов имеет вид `callee(arguments)`. Вызываемым может быть имя или член, поэтому можно вызывать методы значений, лежащих в state. Так значение форматируется в шаблоне:

::demo calls

`{missing.toUpperCase()}` пусто, а не ошибка: вызов тоже null-safe, и вызов чего-то, равного `undefined`, даёт `undefined`. Это скрывает ошибки, как и в случае с точкой, поэтому используйте это осознанно.

Сгенерированный код для вызова — `((state.tags)?.join)?.(", ")`: метод по-прежнему вызывается на `state.tags`, поэтому `this` правильный.

До функции можно добраться только через state или через значение в state. У шаблона нет глобальных переменных: `Math.round(x)` читает поле state с именем `Math`. Если вам нужно вычисленное значение, вычислите его в handler, который меняет state, и храните результат в state (`total`, `visibleItems`, `label`).

> [!WARNING] Optional chaining только для свойств
> `?.` принимается только перед именем свойства. `items?.[0]` и `callback?.()` — ошибки: `Expected property name`. Они вам не нужны, потому что `items[0]` и `callback()` уже null-safe.

## Операторы

Поддерживаются эти операторы, от наивысшего приоритета к низшему:

| Операторы | Значение |
| --- | --- |
| `.` `[ ]` `( )` | член, индекс, вызов |
| `!` `-` `+` (перед значением) | не, смена знака, преобразование в число |
| `*` `/` `%` | умножение, деление, остаток |
| `+` `-` | сложение (или склейка строк), вычитание |
| `<` `>` `<=` `>=` | сравнение |
| `==` `!=` `===` `!==` | равно, не равно, строго равно, строго не равно |
| `&&` | и: первое ложное значение или последнее значение |
| двойная черта | или: первое истинное значение или последнее значение |
| `??` | nullish: правая часть только тогда, когда левая равна `null` или `undefined` |
| `a ? b : c` | тернарный, самый низкий |

Слова «двойная черта» обозначают две вертикальные черты, `||`. Скобки `( )` группируют, как в арифметике.

::demo operators

Обратите внимание на эти строки демо:

- `{qty > 1 && "many"}` здесь равно `"many"`. Если бы `qty` было 1, значением было бы `false`, которое рендерится как ничто: короткий способ сказать «показать этот текст только когда».
- `{qty >= 3 || "few"}` здесь равно `true`, а `true` рендерится как текст `true`. Результат сравнения — булево значение, поэтому `||` — это инструмент запасных значений, а не условий. Когда вам нужен текст, используйте тернарный оператор.
- `{label ?? "no label"}` заменяет `null`.

Разница между `??` и двойной чертой важна для значений вроде `0`. Двойная черта заменяет каждое ложное значение, `??` заменяет только `null` и `undefined`:

::demo nullish

При `count`, равном `0`, первая строка откатывается к `none`, а вторая показывает `0`. Используйте `??`, когда ноль или пустая строка — настоящее значение.

Две вещи отличаются от JavaScript, поэтому будьте осторожны, если копируете выражение из своего кода. Во-первых, нет побитовых операторов, нет `**`, `typeof`, `in`, `new`, нет присваивания (`=`, `++`) и нет оператора запятая. Во-вторых, `??` — обычный оператор, который можно смешивать с `&&` и `||` без скобок. Он связывает слабее, чем `||`: `a ?? b || c` означает `a ?? (b || c)`.

::demo precedence

Когда сомневаетесь, добавьте скобки. В сгенерированном коде они ничего не стоят, потому что компилятор и так ставит собственные скобки вокруг каждой операции.

## Тернарный оператор: выбор значения

`condition ? a : b` выбирает одно из двух значений. Тернарные операторы вкладываются вправо, поэтому цепочка читается как `else if`:

::demo ternary

Во втором шаге счётчик меняется с 2 на 9: меняются обе строки. В первом шаге (с 1 на 2) меняется только первая строка, потому что `few` по-прежнему `few`. Компилятор сравнивает итоговый текст каждой строки, а не входные данные.

Для целого куска страницы, который появляется или исчезает, используйте `if`, а не тернарный оператор. Тернарный оператор создаёт *значение*; `if` создаёт *узлы*.

## Истинность

Там, где ожидается условие (`?:`, `&&`, `||`, `!`, `if`, `class:name=...`), pavlus использует правила JavaScript, потому что сгенерированный код — это JavaScript. Эти значения **ложные**: `false`, `0`, `""`, `null`, `undefined` и `NaN`. Всё остальное истинно.

::demo truthiness

Две строки удивляют тех, кто пришёл из других языков. Пустой массив истинен, поэтому `if items` истинно для пустого списка; пишите `if items.length`, чтобы спросить, есть ли в нём что-нибудь. И строка `"0"` истинна.

## Как значения записываются в виде текста

Дырка в тексте вызывает помощник с именем `toText`. Вот его полное определение из runtime:

```ts
export function toText(value: unknown): string {
  return value == null || value === false ? "" : String(value);
}
```

Так что `null`, `undefined` и `false` становятся пустой строкой. Всё остальное преобразуется через `String(...)`.

::demo text-values

Это сделано намеренно. Благодаря этому `{cond && "text"}` работает как «показать текст, когда условие выполняется», а отсутствующие данные становятся невидимыми. Обратите внимание на три результата, которые могут удивить:

- `0` показывается как `0`. Обычно это то, что вам нужно для счётчика.
- `true` показывается как слово `true`.
- У объекта нет полезного текста: он становится `[object Object]`, а массив — своими элементами через запятую. Если вы видите что-то из этого, вы печатаете целое значение там, где имели в виду поле.

## Как значения записываются в виде атрибутов

Атрибут отличается от текста, потому что атрибут может быть *отсутствующим*. Помощник называется `toAttr`:

```ts
export function toAttr(value: unknown): string | null {
  if (value == null || value === false) return null;
  return value === true ? "" : String(value);
}
```

- `null`, `undefined` и `false` означают **нет атрибута**. Атрибут не рендерится, а если он был раньше, `diff` удаляет его patch-ем `rmAttr`.
- `true` означает атрибут с пустым значением, как `disabled=""`. Так включается булев атрибут.
- Всё остальное — значение в виде строки, включая `0` и пустую строку.

::demo attr-values

Прочитайте результат и три шага. `checked={on}` стал `checked=""`. `disabled=off` отсутствует, потому что `off` равно `false`. `title="{note}"` отсутствует, пока `note` равно `null`, затем шаг добавляет его, а последний шаг удаляет. `data-count=count` сохраняет `0`.

Голый атрибут без значения, такой как `disabled` в `button(disabled)`, вообще не выражение: это фиксированный пустой атрибут.

### Одна дырка или строка с дыркой

Если значение в кавычках — **только** одна дырка, `title="{note}"`, компилятор обрабатывает его точно так же, как `title={note}`, и использует `toAttr`. Если вокруг дырки есть другой текст, `title="Note: {note}"`, всё значение — это строка, собранная склейкой частей, и каждая дырка внутри неё использует `toText`. Строка никогда не бывает отсутствующей.

::demo attr-strings

В первой строке нет `title`, пока `note` равно `null`. Во второй строке `title="Note: "`. Выбирайте первую форму, когда «нет значения» должно убирать атрибут, а вторую — когда вам нужен префикс.

Чтобы показывать или скрывать атрибут по условию, используйте тернарный оператор, возвращающий `null`:

::demo ternary-attr

Здесь `data-state` отсутствует, потому что `busy` ложно, а у `aria-pressed` текст `"true"` или `"false"`. Это также правильный способ записать атрибут, который читает CSS-правило вроде `[data-state="busy"]`: булево `true` дало бы пустое значение и не совпало бы.

## Как компилируется интерполированная строка

Возьмите шаблон с тремя дырками и откройте модуль, который компилятор для него генерирует:

::demo compiled open=module

В `render` текст строится склейкой частей через `+`: литеральные части — это строки JavaScript, а каждая дырка обёрнута в `toText(...)`. Вот строка, которую компилятор написал для шаблона выше:

```ts
text: "" + toText((state.user)?.name) + " wrote " + toText(state.count) + " " + toText(((state.count === 1) ? "post" : "posts"))
```

Поскольку эта строка начинается с дырки, компилятор ставит `""` первым, чтобы результат всегда был строкой, даже если первая дырка — число. Строка, которая начинается с литерального текста, например `Hello, {name}!`, начинается с этого текста.

`diff` строит то же выражение дважды, один раз для `prev` и один раз для `next`, и сравнивает две строки. Поэтому patch — это одна операция `text` с полным новым текстом, и поэтому неизменный текст ничего не порождает. Комментарий `(reads: user, count)` в сгенерированном коде — это список имён, которые читает узел. Строка `if (prev.user !== next.user || prev.count !== next.count)` под ним — это защита, которая пропускает работу, если ничего из этого не изменилось.

Каждый оператор в результате обёрнут в скобки, каждый доступ к члену — в `?.`, каждый вызов — в `?.( )`. Ничего не вычисляется во время компиляции, и ничто в вашем выражении не может выйти за пределы state: скомпилированная функция видит только `state`, помощников и значения, которые строит сама.

## Экранирование скобок

Буквальная `{` в тексте начинает дырку. Чтобы написать скобку, поставьте перед ней обратную косую черту. Скобку `}`, которая не закрывает дырку, можно писать как есть.

::demo escapes

`\{` и `\}` — единственные escape-последовательности в тексте. Внутри значения атрибута в кавычках они тоже работают. С кавычками иначе: внутри `"..."` нельзя написать двойную кавычку (обратная косая черта остаётся в значении), поэтому используйте одинарные кавычки вокруг значения, `title='He said "hi"'`, или поместите строку в дырку.

## Что не поддерживается

Язык намеренно маленький. Так компилятор проще понимать, каждую зависимость узла можно перечислить на этапе компиляции, а шаблон не может выполнять произвольный код. Вот что вы попробуете в первую очередь и какую настоящую ошибку получите.

```pavlus-invalid
p {items.map(x => x.name)}
```

Стрелочная функция: `Unexpected character "=" (line 1, col 16)`.

```pavlus-invalid
p {`Hello ${name}`}
```

Шаблонная строка: `Unexpected character "`" (line 1, col 4)`. Вместо неё используйте `"Hello {name}"` в атрибуте или текст с дырками.

```pavlus-invalid
p {count = 1}
```

Присваивание: `Unexpected character "=" (line 1, col 10)`. Шаблон никогда не меняет state. Это делают события, отправляя messages вашему коду.

```pavlus-invalid
p {typeof user}
```

Операторы JavaScript, которых нет в таблице: `Unexpected "user" (line 1, col 11)`. Слово `typeof` читается как имя, и тогда перед `user` нет оператора.

```pavlus-invalid
p {a, b}
```

Оператор запятая: `Unexpected "," (line 1, col 5)`. Запятые только разделяют аргументы вызова и элементы массива.

```pavlus-invalid
p {}
```

Дырка без содержимого: `Empty expression (line 1, col 4)`.

```pavlus-invalid
p {name
```

Дырка, которая так и не закрыта: `Unclosed { (line 1, col 1)`.

Общий ответ на всё это один: делайте работу там, где меняется state, в handler, а в state храните готовое к показу значение. Тогда шаблон только читает значения и выбирает между ними.

## Что вы узнали

- `{expr}` может быть в тексте, в значении атрибута в кавычках или быть целым значением атрибута (`alt={x}` или `alt=x`).
- В языке есть литералы, имена, `.` и `[ ]` (оба null-safe), вызовы, унарные и бинарные операторы, `?:` и массивы. Ничего не присваивается, нет стрелочных функций и шаблонных строк.
- `null`, `undefined` и `false` — это пустой текст и отсутствующий атрибут; `true` — пустой атрибут; `0` и `""` — значения.
- Компилятор превращает строку с дырками в `"literal" + toText(expr) + ...` и сравнивает результат для `prev` и `next`, чтобы решить, нужен ли patch.
