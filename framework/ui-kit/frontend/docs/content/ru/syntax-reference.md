## Как пользоваться этой страницей

Эта страница — справочник. Она коротко повторяет то, что четыре предыдущие страницы объясняют шаг за шагом: [элементы](page:syntax-elements), [выражения](page:syntax-expressions), [события](page:syntax-events), [условия и циклы](page:syntax-control-flow) и [компоненты](page:syntax-components). Сначала прочитайте их, если строка ниже вам непонятна. Возвращайтесь сюда, когда нужно проверить написание.

Шаблон — это текстовый файл. Он компилируется в модуль с двумя чистыми функциями: `render(state)` возвращает виртуальные узлы, а `diff(prev, next)` возвращает список patch между двумя состояниями. Всё, что описано ниже, — это то, что вы можете написать в файле.

## Строки

Каждая непустая строка — это одна сущность. Отступ (только пробелы) вкладывает строку в строку выше.

| Вы пишете | Это | Примечания |
| --- | --- | --- |
| `tag.class#id(attrs) text` | элемент | любую часть можно опустить, кроме первой из tag, class или id |
| `.card`, `#app` | `div` | тег по умолчанию — `div` |
| строка, начинающаяся с вертикальной черты, затем текст | текстовая строка | один текстовый узел; дырки разрешены |
| `{expr} more text` | текстовая строка | строка, начинающаяся с `{`, — тоже текст |
| `// note` | комментарий | отбрасывается; завершающий `// note` после пробела тоже отбрасывается |
| `if expr` | начало условия | двоеточие в конце необязательно |
| `else if expr`, `else` | следующие ветки | должны идти за `if` с тем же отступом |
| `for item in list` | цикл | `for item, i in list key expr` добавляет индекс и key |
| `import Name from "path"` | импортирует дочерний компонент | только в начале файла, имя начинается с заглавной буквы |
| `+Name#id(props)` | встраивает (embed) импортированный дочерний компонент | `#id` необязателен |
| `+{expr}#id(props)` | встраивает (embed) view, которое лежит в значении | `#id` обязателен |
| `+outlet` | дочерний компонент маршрута | после него ничего не пишется |

У void-элементов (`area`, `base`, `br`, `col`, `embed`, `hr`, `img`, `input`, `link`, `meta`, `source`, `track`, `wbr`) не может быть дочерних строк.

Текст склеивается: две текстовые строки подряд или встроенный текст элемента и следующая за ним текстовая строка разделяются переводом строки, который HTML показывает как пробел.

::demo comments

## Атрибуты

Атрибуты записываются в круглых скобках после тега, через пробелы или запятые. Имена могут содержать буквы, цифры, `_`, `-`, `:`, `.` и `@`.

| Вы пишете | Значение |
| --- | --- |
| `disabled` | булев атрибут, присутствует с пустым значением |
| `type="button"` | фиксированная строка |
| `title="Open {name}"` | строка с дырками; каждая дырка следует правилам текста |
| `href=url`, `value=user.name` | выражение, одно слово без пробелов |
| `title={a + " " + b}` | выражение с пробелами, в фигурных скобках |
| `title="{note}"` | то же, что `title={note}`: только одна дырка |
| `class:on=cond` | добавляет класс `on`, когда `cond` истинно |
| `class="a b"` | классы, объединяются с классами из `.a` и `class:` |
| `@click=save` | привязка события, message `save` |
| `@click.prevent.stop=save(item.id)` | то же, с модификаторами и payload |
| `\{` и `\}` | буквальная фигурная скобка в тексте или в значении в кавычках |

Значение `class:name` или `@event` должно быть выражением: `class:on` без значения — это ошибка.

## Значения в тексте и в атрибутах

Одно и то же значение выводится по-разному в тексте и в атрибуте.

| Значение | В тексте `{v}` | В атрибуте `a=v` |
| --- | --- | --- |
| `null`, `undefined` | ничего | атрибута нет |
| `false` | ничего | атрибута нет |
| `true` | слово `true` | атрибут с пустым значением |
| `0` | `0` | `a="0"` |
| пустая строка | ничего | `a=""` |
| число или строка | её текст | её текст |
| массив | элементы через запятую | то же |
| объект | `[object Object]` | то же |

В строке из нескольких частей, например `title="Note: {v}"`, каждая дырка следует колонке для текста, а атрибут присутствует всегда.

## Выражения

Всё внутри `{ }` и каждое значение атрибута без кавычек разбирается как выражение.

| Группа | Что поддерживается |
| --- | --- |
| литералы | числа (`1`, `.5`, `1e3`), строки (`"a"`, `'a'`), `true`, `false`, `null`, `undefined`, массивы `[a, b]` |
| имена | поле state или переменная цикла |
| доступ к полю | `a.b`, `a?.b` (оба null-safe) |
| индекс | `a[expr]` (null-safe) |
| вызов | `f(x, y)`, `a.b(x)` (null-safe) |
| унарные | `!a`, `-a`, `+a` |
| арифметика | `*` `/` `%`, затем `+` `-` |
| сравнение | `<` `>` `<=` `>=`, затем `==` `!=` `===` `!==` |
| логика | `&&`, затем двойная вертикальная черта, затем `??` |
| тернарный | `a ? b : c`, вкладывается вправо |
| группировка | `( )` |

Не поддерживаются: литералы объектов, шаблонные строки, регулярные выражения, присваивание, `++`, `typeof`, `in`, `new`, `**`, побитовые операторы, оператор запятая, `?.[ ]` и `?.( )`. Стрелочные функции есть, но только с телом-выражением (`x => x.on`). Имена ищутся только в state: глобальных имён нет.

Истинность та же, что в JavaScript: `false`, `0`, `""`, `null`, `undefined` и `NaN` ложны; пустой массив и пустой объект истинны.

## События

| Часть | Значение |
| --- | --- |
| `@click` | имя DOM-события (любое событие, которое может вызвать элемент) |
| `=save` | id message; точки разрешены: `users.open` |
| `(a, b)` | аргументы; ноль аргументов — нет payload, один — это payload, несколько образуют массив |
| `.prevent` | `preventDefault()` перед отправкой message |
| `.stop` | `stopPropagation()` перед отправкой message |

Message, который доходит до приложения, имеет вид `{ id, payload, event }`, где `event` — это `{ type, value?, checked?, key? }`. У message, отправленных встроенным (embed) дочерним компонентом, перед id стоит имя экземпляра (`row.toggle`). Неизвестный модификатор игнорируется, а если одно и то же событие привязано дважды, побеждает последняя привязка.

## Компоненты

| Вы пишете | Значение |
| --- | --- |
| `import Card from "./card.pavlus"` | делает `Card` доступным |
| `+Card` | встраивает его (embed), имя экземпляра `card` |
| `+Card#intro(title="Hi")` | явное имя экземпляра, фиксированный prop |
| `+Card(title=post.title count=3 active)` | props-выражения сохраняют тип; голое имя означает `true` |
| `+Card(...post)` | раскрывает поля объекта; более поздние props побеждают |
| `+{view}#slot(...)` | view или компонент из state; `null` ничего не выводит |
| `+outlet` | страница, выбранная таблицей `routing` компонента |

Дочерний компонент видит в качестве своего state только свои props. Имя экземпляра служит префиксом его message, префиксом id его узлов и, в логике, ключом в `children`.

## Что может вернуть `diff`

Patch — это обычные данные. Вот все их виды.

| `op` | Поля | Создаётся, когда |
| --- | --- | --- |
| `text` | `id`, `text` | изменился текст узла |
| `attr` | `id`, `name`, `value` | атрибут получил новое значение |
| `rmAttr` | `id`, `name` | атрибут стал `null` или `false` |
| `handler` | `id`, `event`, `msg` | изменился message привязки |
| `insert` | `before`, `nodes` | появилась ветка, элемент или дочерний компонент |
| `clear` | `from`, `to` | всё между двумя маркерами удалено |
| `remove` | `from`, `to` | элемент с key удалён вместе со своими маркерами |
| `move` | `from`, `to`, `before` | элемент с key поменял место |

## Ошибки, о которых сообщает компилятор

Каждое сообщение заканчивается строкой и колонкой. Если компилятору передано имя файла, как это делает plugin для Vite, сообщение начинается с него: `page.pavlus: Empty expression (line 1, col 4)`. Это настоящие сообщения, каждое — из шаблона, который его вызывает.

```text

Inconsistent indentation (line 3, col 1)
This line cannot have children (line 2, col 1)
Cannot parse line "%x" (line 1, col 1)
Unexpected "!" (line 1, col 2)
Unclosed ( (line 1, col 2)
Unterminated string (line 1, col 5)
Unexpected "=" in attributes (line 1, col 5)
Unexpected "?" in attributes (line 1, col 7)
Unexpected "/" (line 1, col 5)
Unclosed { (line 1, col 1)
Empty expression (line 1, col 4)
Expected ":" (line 1, col 9)
Expected property name (line 1, col 7)
Unexpected "b" (line 1, col 6)
Unexpected character "=" (line 1, col 6)
"@click" needs an expression value (line 1, col 8)
"class:on" needs an expression value (line 1, col 4)
Event handler must be a message id like `save` or `remove(item)` (line 1, col 8)
`else` without matching `if` (line 1, col 1)
`...spread` is only allowed in component props (+Name(...)) (line 1, col 3)
```

Сообщения о компонентах:

```text
"card" cannot be used as a component name (start with a capital letter, not String/Array/Map/Set/Error) (line 1, col 1)
"Card" is imported twice (line 2, col 1)
`import` lines must be at the top of the file (line 2, col 1)
"Card" is not imported. Add `import Card from "..."` or use +{Card} for a component that comes from the state (line 1, col 2)
Unexpected "x" after component (line 2, col 8)
Instance name must be an identifier (line 2, col 6)
"data-x" is not a valid prop name (line 2, col 7)
A dynamic component needs an instance name: +{expr}#name(...) (line 1, col 7)
`+outlet` takes nothing after it (line 1, col 8)
Expected a component name or {expression} after + (line 1, col 2)
```

Две ошибки компилятор не находит, они возникают во время выполнения: `pavlus: duplicate key 1` (у двух элементов цикла одинаковый key, ошибку выбрасывает `diff`) и `pavlus: +{...} needs a view or a component with a view`.

Одно замечание о колонке для `Unclosed {`: она считается от начала текста строки, а не от начала самой строки, поэтому может быть меньше, чем вы ожидаете. Номер строки верный.

## Частые ловушки

Это ошибки, которые люди совершают чаще всего. Первые из них не дают вообще никакой ошибки, поэтому они самые дорогие.

- **Кавычки определяют смысл.** `class="x"` — это текст `x`; `class=x` читает поле state `x`. `target=_blank` читает поле с именем `_blank`, ничего не находит и отбрасывает атрибут. Пишите `target="_blank"`.
- **Тексту нужна вертикальная черта.** Строка из одних слов — это элемент: `Hello world` — это `<Hello>world</Hello>`. Текст на отдельной строке начинается с `|`.
- **Циклу нужно слово `in`.** `for x of xs` читается как элемент с именем `for`. На странице вы получите `<for>` и никакой ошибки.
- **Ноль показывается.** `{count && "items"}` выводит `0`, когда `count` равен `0`, потому что `0` — это значение, а не ничто. Используйте `{count > 0 && "items"}` или тернарный оператор.
- **Пустой массив истинен.** `if items` истинно для `[]`. Пишите `if items.length`.
- **Голое значение заканчивается на пробеле.** `title=a + b` и `class:on=a === b` падают с `Unexpected "=" in attributes` или `Unexpected "?" in attributes`. Оберните выражение: `title={a + b}`.
- **Голое значение — это выражение.** `href=/docs` падает с `Unexpected "/"`. Пути берите в кавычки: `href="/docs"`.
- **Двойная кавычка внутри значения в двойных кавычках** сохраняет обратный слэш. Возьмите значение в одинарные кавычки.
- **Optional chaining.** `a?.[0]` и `f?.()` — это ошибки. Индекс и вызов уже null-safe.
- **Опечатки молчат.** Неверное имя поля выводится как пустой текст, а message без handler ничего не делает.
- **Keys.** Без `key` ключом служит позиция, и список с изменённым порядком перезаписывается. Повторяющиеся key вызывают исключение в `diff`, а не в первом `render`.
- **Несколько аргументов меняют payload.** `@click=pick(id)` отправляет значение; `@click=pick(id, kind)` отправляет массив. Handler должен с этим совпадать.
- **Шаблон не вызывает handlers.** `@click=save(item)` ничего не вызывает: он строит message `save` с payload.
- **Сначала imports.** Строки `import` — в начале, а для `+Name` нужен соответствующий import. Для view, которое приходит из state, используйте `+{name}#id`.
- **У void-элементов нет дочерних элементов.** У `input`, `br`, `img` и остальных не может быть строк с отступом.

## Собираем всё вместе: форма

Форма регистрации, которая использует события с модификаторами, переключатели `class:`, условия для ошибок, булевы атрибуты и тернарный оператор для текста кнопки.

::demo form

State хранит всё, что нужно странице: значения, карту `errors` и флаги `busy` и `done`. Handlers вашего компонента меняют его, а шаблон только описывает каждую ситуацию.

- **Появляются ошибки валидации.** Поле имени получает класс `invalid` (`attr`), а два сообщения об ошибках вставляются на место своих `if`. Поле email, у которого нет ошибки, не затрагивается.
- **Вводится имя.** Обновляются значение поля, класс и ошибка этого поля. Ошибка условий остаётся.
- **Отправка.** Три patch на одной кнопке: появляются `disabled` и `class`, и меняется текст. `disabled={busy}` до этого `false`, а после — `true`, поэтому атрибут добавляется и убирается; `toAttr(true)` — это пустое значение.
- **Готово.** Кнопка восстанавливается, и вставляется message `success`.

`@submit.prevent=submit` на форме не даёт браузеру перезагрузить страницу. Handler `submit` читает значения из state, потому что каждое поле скопировало туда свое значение через `@input`.

## Собираем всё вместе: таблица с фильтрами

Таблица пользователей с кнопками фильтра, полем поиска и действиями в каждой строке. Список, который показывает таблица, — это `visible`, его вычисляет компонент из полных данных, фильтра и запроса. Шаблон сам не умеет фильтровать и считать, поэтому это делает handler, а шаблон показывает результат.

::demo table

- **Фильтр: paused.** Кнопки фильтра находятся в цикле с key, и класс `active` переходит с одной на другую. Строки двух других пользователей удаляются, а текст в подвале обновляется.
- **Фильтр: никто.** Последняя строка удаляется, и `if` для пустой строки вставляет "No users match".
- **Bob возобновлён.** Строка остаётся на своём месте. Её класс `paused` убирается, подпись её кнопки меняется, а patch `handler` даёт кнопке новый payload `[2, "active"]`. Два аргумента: массив.
- **Порядок обращён.** Строки с key перемещаются, а не перезаписываются.

## Собираем всё вместе: панель с вкладками

Панель вкладок, построенная из данных, и тело, которое показывает одну из трёх панелей. Панель вкладок — это цикл с key и `class:active`, а панель — это `if` / `else if` / `else`.

::demo tabs

- Переключение вкладки меняет две кнопки (у каждой класс и `aria-selected`, записанный как текст `"true"` или `"false"`, потому что ARIA нужны слова, а не пустой атрибут) и **заменяет** тело: ветка изменилась, поэтому `clear` и `insert`.
- Когда приходит новое событие при открытой вкладке активности, ветка остаётся той же. Меняется только список: один `insert` для нового элемента, потому что цикл использует в качестве key текст события.

Это весь язык. Всё остальное, например то, что plugin для DOM делает с patch, как store меняет state и как маршрутизируются страницы, находится в компонентах и plugins.

## Что вы узнали

- Шаблон — это строки: элементы, текстовые строки, `if` / `for`, imports и embed. Атрибуты несут классы, события и props.
- У значений есть фиксированные правила: `null`, `undefined` и `false` — это ничто; `true` — пустой атрибут; `0` и `""` — значения.
- Ошибки компилятора короткие и содержат строку и колонку; опасны те ошибки, которые допустимы, но означают другое.
- Большие страницы строятся из тех же нескольких частей: state с готовыми к показу значениями, условия, циклы с key и события с payload.
